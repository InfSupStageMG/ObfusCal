# Code of Conduct

## Our commitment

We want ObfusCal to be a respectful, welcoming project for contributors, users, and reviewers. Everyone participating in
the project is expected to act professionally and constructively, regardless of experience level, identity, background,
religion, disability, nationality, or other personal characteristics.

## Expected behaviour

Examples of behaviour that help create a positive environment include:

- being respectful in discussions, reviews, and issue triage
- assuming good intent and asking clarifying questions before escalating
- giving and receiving feedback constructively
- focusing criticism on ideas, code, and behaviour rather than people
- helping newcomers understand project context, constraints, and standards

## Unacceptable behaviour

Examples of unacceptable behaviour include:

- harassment, discrimination, intimidation, or personal attacks
- sexualised language or imagery in project spaces
- trolling, repeated hostility, or deliberately inflammatory behaviour
- publishing private information without explicit permission
- spam, impersonation, or sustained disruption of discussions or reviews

## Scope

This Code of Conduct applies in all project spaces, including:

- GitHub issues, pull requests, and reviews
- documentation discussions and architecture notes
- any public or private communication channels used for project collaboration

## Reporting

If you experience or witness unacceptable behaviour, contact the repository maintainers through any private contact
route listed on the repository or maintainer profile. If no private route is available, open a minimal GitHub issue
requesting maintainer follow-up without including sensitive personal details.

For security vulnerabilities, do **not** use the Code of Conduct reporting path.
Follow the instructions in `.github/SECURITY.md` instead.

## Maintainer responsibilities

Project maintainers are responsible for clarifying and enforcing this Code of Conduct. They may remove, edit, or reject
comments, commits, issues, or pull requests that violate it, and may temporarily or permanently restrict participation
when necessary to protect the project and its community.

## Enforcement guidelines

When responding to violations, maintainers should aim to:

- stop the harmful behaviour quickly
- protect the reporting person from retaliation where possible
- document the incident and the response
- apply consequences proportionally and consistently

## Attribution

This document is informed by widely used open-source community conduct standards, adapted for this repository and its
maintainer workflow.
